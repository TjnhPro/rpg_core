## Gate B limitations (historical)

- This is targeted verification, not the final full regression or exact-head
  release CI. Full verify/commit/push/release PR require Gate B approval.
- The archive is cleaned up by the existing consumer harness. Hash, integrity,
  content equality and scenario observations are retained in local verification
  logs; artifact byte identity is per run/platform, not a cross-platform claim.
- Historical mode needs Git history, npm access/cache and installed Node tooling.
  It builds/audits historical architecture; it does not rerun the historical full
  regression as a substitute for executing the current candidate.
- Scenario coverage is finite. Text RPG/Võ Lâm/ARPG are numerical integration
  subsets, not complete game runtimes or commercial formula replicas.
- Tooling authorization is pinned in reviewed code; it is not a signature against
  an attacker rewriting both validator and policy. Such changes require review.
- Release notes remain candidate notes. No release PR/merge, tag, GitHub Release,
  npm publish, license or version beyond 2.0.0 is authorized/performed here.
