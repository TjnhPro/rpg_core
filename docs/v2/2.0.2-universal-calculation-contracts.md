## Public inventory and field ownership

All **39** exports are type-only, through `@rpg/core/kernel`. Root and existing
entrypoints do not re-export Kernel. No new subpaths, runtime exports, production
dependencies, package version or preservation amendments are introduced. Native ESM
namespace keys remain empty. Supporting declarations stay within Kernel.
Required/optional fields and their generic narrowing are declared in the linked
canonical contracts; each family can be used independently.

### common

[common.ts](../../src/kernel/contracts/common.ts): `Identifier`, `Scalar`, `NumericValues`, `NumericBounds`, `DecimalPrecision`, `NumericRule`, `CalculationIssue`.

Identifier policy approved for future generic validation: nonempty strings, no trimming, case folding or Unicode normalization; exact code-unit identity. No universal ASCII regex or arbitrary maximum length. Game IDs can contain punctuation/Unicode. Application/Legacy boundaries retain their existing length, vocabulary and collection budgets. Future generic numerical validators must reject nonfinite numerical inputs where the approved primitive requires finite numbers; each primitive owns sign/range constraints. Bounds are optional independently; omitted sides are unbounded, explicit bounds must be finite and ordered. A `number` alias does not enforce any of this at runtime.

`DecimalPrecision` means the existing `Number(value.toFixed(decimalPlaces))` convention, followed by re-clamp when used by stat resolution. Contract valid decimalPlaces: integer 0..100, matching JavaScript toFixed rather than an arbitrary game limit. Omission means no decimal rounding. This version supplies no validator or rounding function.

### modifiers

[modifiers.ts](../../src/kernel/contracts/modifiers.ts): `ModifierOperation`, `ModifierIdentity`, `NumericalModifier`, `ModifierResult`.

Source is a game-defined key, never a closed list. No conditions, ownership sets, predicates or lifecycle. `enabled` is already resolved numerical eligibility; Legacy filters active sources and validates the complete Legacy payload before projection. Identity is the tuple `(source, sourceInstanceId, id)`. Future canonical ordering retains lexical comparison of `JSON.stringify([source, sourceInstanceId, id])` using `<`/`>`, not localeCompare and not caller array order. Identical duplicates deduplicate; conflicting projected numerical payloads reject. Legacy must additionally preserve its full-payload conflict detection before projecting away gameplay fields. Contributions preserve numerical input references; Legacy adapters retain original contribution references through tuple mapping, not cloned gameplay objects embedded in Kernel.

No operation or formula changes: `(base + sum(flat)) * (1 + sum(percent)) + sum(points)`. Preserve floating-point summation order.

### stats

[stats.ts](../../src/kernel/contracts/stats.ts): `AttributeScaling`, `DerivedStatRule`, `StatCalculationInput`, `StatBreakdown`, `StatCalculationResult`.

Caller supplies attribute bases, baselines, selected rules and extras. Kernel will own numeric sequencing only after .4 extraction. Scaling arrays carry explicit evaluation order; Legacy supplies its four historical attributes in their existing order. `training` retains a numerical configuration parameter; it is NOT implicitly added by the stat loop. Current resolveCharacterStats uses passed extras, not rule.training, as an additive term. New callers resolve training contributions into flatContributions explicitly. Transform callbacks must be pure, caller-supplied numeric functions, never live entity lookups; they are not part of snapshot data.

Preserve attribute resolution first, then derived Base → Attribute Scaling → explicit flat extras → Modifiers → Transform → Bounds → Precision → re-clamp. Legacy explicitly maps precision 4 and current disabled-stat rules; Kernel imposes no universal 4-place default. A sparse baseStats uses the corresponding explicit rule.default, without inventing a missing stat registry.

Approved review adjustment: `attributeDetails[A]` stores the final numerical
attribute base, modifier result, uncapped and effective value. Derived
`details[S]` stores base, scaling, flat, resolved, uncapped and value. Legacy can
project `attributes` and `values` directly, `core` from attributeDetails,
`details` from stored derived fields, and `scaling` from details[id].scaling.
No repeated scaling, transform or modifier resolver call is needed. These are
keyed numerical records, not a copy of the fixed Legacy character schema.
The compile-only fixture demonstrates all five projections using field reads.

Transform invocation boundary: synchronous, once per derived stat after modifier
resolution and before clamp/precision, including disabled derived stats (matching
calculateEffectiveStat's current evaluation order). No attribute transform is
called; an omitted callback is identity. Callers must provide pure functions:
same numerical argument yields the same return, without side effects, clocks,
RNG or mutable-state lookups. TypeScript rejects Promise returns but cannot prove
purity, finite results or determinism of closures. No Formula DSL or callback
snapshot is implemented. This is a contract for future extraction, not a claim
that Kernel currently executes transforms.


### damage

[damage.ts](../../src/kernel/contracts/damage.ts): `NumericContribution`, `DamageScaling`, `ResolvedDamageBonus`, `DamageCalculationInput`, `DamageCalculationResult`.

Configuration here is the explicit perRank coefficient and already selected/resolved numeric terms; no framework-level algorithm selector or bundled DamageSettings. Caller supplies rank (Legacy maps omitted rank to 1), coefficient/source ordering, eligible bonus values and additive criticalBonus. Flat includes definition/input flat; flatContributions preserve ordered numerical provenance. The .5 adapter must retain original modifier contributions and options metadata for its existing result rather than demand gameplay payloads in Kernel. `reason` is opaque diagnostic text resolved by the caller, not a predicate language. Ineligible bonuses have effective zero contribution, while their identity/reason remains representable.

B0 rank behavior and B1 arithmetic stay as audited, including existing nonnegative clamps and no damage rounding. DamageResult stops before defense. Legacy assembles its unchanged rich result and orchestrates hit/critical/mitigation. This permits a .5 B0/B1 extraction without a Kernel → Legacy Defense edge. Approval of these contracts does not approve the later .5/.6 implementation cut.

### defense

[defense.ts](../../src/kernel/contracts/defense.ts): `RandomRoll`, `ProbabilityRule`, `HitCalculationInput`, `HitCalculationResult`, `CriticalCalculationInput`, `CriticalCalculationResult`, `RatingMitigationRule`, `MitigationCalculationInput`, `MitigationCalculationResult`.

Caller selects armor/resistance/another rating key and resolves delivery eligibility; Kernel does not select based on Physical/Magic or DamageDelivery. Absent coefficients/levels remain representable and yield future missing_config diagnostics rather than defaults. Preserve audited rating formula, positive level gap and clamps; adapter retains old config/version and full result context.

Critical `bonus` is the existing additive bonus to the B1 sum, with multiplier = 1 + bonus as a diagnostic. Do not convert bonus → multiplier → bonus for arithmetic: subtracting 1 can alter floating-point results. The reported multiplier does not introduce an independent post-B1 multiplication.

RNG alternatives:

| Option | Dodge-before-Crit and calls | Assessment |
| --- | --- | --- |
| Lazy per-step `RandomRoll` | Legacy calls hit first; calls critical only after a landed hit. Each primitive requests its roll lazily. Existing numeric roll inputs also map directly. | Selected. Smallest compatibility mapping, no stored RNG/session and no eager pair. |
| Deterministic per-step numeric rolls only | Can preserve behavior if caller first resolves whether Dodge needs a roll, runs Dodge, then obtains Crit roll only if required. Needs a planning/result protocol or duplicated chance checks in caller. | Viable later, but unnecessary extra public protocol now. Never pre-sample two rolls. |

Approved decision: lazy per-step RandomRoll; no combined eager rolls object, implicit Math.random, or RNG in snapshots. No runtime functions in .2.

Future Legacy parity requirements: Dodge first; no Dodge draw when disabled/ineligible/chance zero. Dodge success suppresses Crit entirely. For a landed eligible non-DoT hit, Crit draws once even when effective critical chance is zero, matching current calculateDamage. DoT draws neither; Legacy preserves its historical critical.roll = 1 on that path when mapping a skipped generic result. Crit clamp [0,.85] is explicitly supplied by Legacy. Dodge currently validates a consumed roll in [0,1]; Crit currently does not validate its numeric roll the same way. Do not silently strengthen the old Crit rejection behavior in a later adapter. Types do not enforce finite/range rules.

### resources

[resources.ts](../../src/kernel/contracts/resources.ts): `ResourceTransitionRule`, `ResourceTransitionInput`, `ResourceTransitionResult`, `ResourceNormalizationInput`, `ResourceNormalizationResult`, `ResourceRegenerationInput`.

Regeneration uses ResourceTransitionResult. Resource identity is an opaque label, not a lookup into a store. Single scalar operations only. Normalization explicitly initializes an omitted current to maximum, otherwise clamps it. Legacy resolves regeneration eligibility after normalization, using its existing alive/current-HP condition, and supplies elapsedMs/1000 and precision 12. Future regen preserves max(current, rounded candidate), so rounding cannot spend a living fraction; adapters keep overflow handling and result/error messages.

Transition amount is nonnegative magnitude; operation supplies direction. Explicit currentAboveMaximum and allowIncreaseFromMinimum preserve damage vs healing/MP asymmetry and no-revival without hardcoding HP. Damage's applied amount can differ from before-after when above-max clamping occurs; do not derive applied generically from that subtraction. Future decrease mapping must preserve min(current,amount), clamped after, and reachedMinimum as a transition (before > minimum && after === minimum). Increase maps actual after-before with overflow-safe bounded addition. No events, state writes, death policy, entity or multi-resource engine.

### snapshots

[snapshots.ts](../../src/kernel/contracts/snapshots.ts): `CalculationContext`, `NumericalOffenseSnapshot`, `CalculationSnapshot`.

Two focused snapshot shapes avoid a generic arbitrary-payload framework. NumericalOffenseSnapshot is component-independent; definition/rank/target/rolls are supplied later. CalculationSnapshot retains independent readonly values, numerical rules and modifier provenance. Selected probability/mitigation rule records can be held by the caller alongside these snapshots; a universal bundled player configuration is unnecessary. Context labels have no trust or runtime authority and do not trigger hidden lookups. No timestamp or scheduler required. Capture timing, clone/freeze and authoritative ownership remain caller/Legacy responsibilities; readonly does not guarantee detached storage or runtime immutability. All snapshot shapes contain only copyable data, no callbacks/RNG. .8 will implement approved detachment semantics.

Approved review adjustment: TypeScript readonly restricts writes through typed
references at compile time. A detached copy owns independent backing objects;
readonly alone does not create one. Runtime freeze rejects/prevents writes at
runtime; deep immutability requires freezing nested objects too. v2.0.2 implements
neither copy nor freeze and does not guarantee independent backing storage.
v2.0.8 owns their separately reviewed implementation and guarantees. These
limitations also appear in public source/emitted declaration JSDoc.

## Architecture and declaration verification

The existing [checker](../../scripts/check-architecture.mjs) retains source-edge,
shim registration, duplicate and cycle checks. Shared compiler-API traversal starts
from Kernel exports and follows bound symbols/declarations, aliases, supporting
nodes, inheritance, generic constraints/defaults, type queries/import expressions,
namespace exports and barrels. Non-default-library declarations must remain under
Kernel. Unresolved reachable public references fail closed. Diagnostics show the
public export/support trail and forbidden declaration path.

The source Program emits declarations in memory; a separate emitted Program
checks its closure under dist/kernel, without relying on stale on-disk output.
The installed consumer invokes the same traversal over actual packed declarations.
Compiler default-library helpers are permitted. No duplicate standalone checker
is introduced. Both declaration and source gates run on invalid CLI fixtures so
source lint cannot mask a declaration test result.

[Declaration fixtures](../../tests/tooling/kernel-declarations.test.ts): 64 tests:
48 valid-target negative source/emitted cases across 12 dependency forms and two
import locations; two positive recursive/internal-support cases; two unresolved
reference rejections; 12 end-to-end CLI negative cases, each with a positive
source-to-emitted baseline. Emitted adversarial tests call the exact shared
traversal on actual .d.ts trees; they are independent of source-edge rejection.
The 71 existing architecture tests remain intact. Target existence and exact
boundary diagnostics are asserted; missing-file/syntax failures are not PASS.

[Compile-only fixtures](../../tests/fixtures/kernel-contracts.ts) construct every
public type, use custom attributes/stats/damage/source/tag keys and independently
represent Text RPG, Vo Lam and ARPG numerical inputs. No entity/Skill/Mechanics/
Spatial types or gameplay objects are required. Eight negative type assertions
cover readonly, generic keys, operations, optional semantics, async transforms and
callbacks excluded from snapshots. These fixtures are copied into the external
installed consumer with their sole Core import changed to @rpg/core/kernel.
They are type expressiveness/isolation evidence, not numerical parity or three
running games. Runtime consumer verification belongs to v2.0.11.

## Limitations and subsequent ownership

No runtime finite/identifier validator, calculation, adapter, clone/freeze or
snapshot capture exists in Kernel. TypeScript permits NaN as number and cannot
prove callback purity or prevent mutation through another alias. Structural
analysis cannot identify a copied gameplay schema merely from its meaning if it
is independently rewritten inside Kernel; semantic review is still necessary.
Unknown downstream applications are not certified by these fixtures.

Modifier extraction starts only in v2.0.3 after separate approval/acceptance.
Stats .4 owns numerical implementation and projection parity; Damage/Defense
.5/.6 owns exact breakdown/RNG parity and a reviewed staged dependency cut;
Resources .7 owns transition/rejection/overflow parity; snapshots .8 owns capture,
copy/freeze and identity/timing guarantees. No later milestone started here.
Stop for Developer review; no automatic merge, release or publication.
