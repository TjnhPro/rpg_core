## Public API and adaptation

Three runtime exports are added only to `@rpg/core/kernel`:

| API | Responsibility |
| --- | --- |
| `calculateEffectiveValue` | Resolve once, transform, clamp, precision and re-clamp |
| `calculateStats` | Ordered attribute pass then ordered derived-stat pass, with complete diagnostics |
| `calculateCooldownDurationMs` | Existing resolved cooldown validation and multiplication |

Approved additive contracts are `PreparedStatCalculationInput` and
`StatModifierResolver`, plus an optional fourth `Resolved` generic on
`StatBreakdown` and `StatCalculationResult`. Its default is the v2.0.2
`ModifierResult<A | S, Source>`; compile assertions retain the old default types.
All 39 existing Kernel type exports remain. Kernel now has 44 symbols: 41 types
and three runtime functions, with nine declaration files in its closed graph.
There are no root re-exports, new package subpaths or package metadata changes.

Prepared input omits raw modifiers and requires complete, unique explicit
attribute/stat order arrays. These are caller preconditions, without a new
runtime schema validator. The resolver is the sole modifier dependency.

| Legacy API | Delegation |
| --- | --- |
| `cooldownDurationMs` | Same signature; delegates Kernel cooldown arithmetic |
| `calculateEffectiveStat` | Adapts bounds/enabled/optional precision; delegates scalar evaluation; keeps original result references |
| `resolveCharacterStats` | Maps fixed IDs, rules/defaults, elemental enablement, dodge override, baselines, extras and transforms; delegates one batch pass |
| `updateCurrentResources` | Unchanged source declaration/body/fingerprint; remains Legacy |

Legacy reconstructs exactly `{attributes, core, values, details, scaling}` from
stored Kernel outputs. Its core/details remain `{value, uncapped, resolved}`;
no additional resolver or arithmetic pass is used to build diagnostics.
Resolved objects, contribution arrays and contribution objects retain identity.
Legacy declarations retain mutable semantics. Kernel output readonly types do
not imply a detached copy or runtime freeze; v2.0.8 owns those guarantees.

## Numerical and error semantics

The sequence is: attributes and their bounds; derived base/default; ordered
scaling using resolved attributes minus caller baselines; flat extras; modifier
resolver; transform; bounds; precision; re-clamp. Scaling starts at zero and adds
in Legacy attribute order. The input sum remains `(base + scaling) + flat`.
Disabled scaling adds zero; `training` is not implicitly added.

Transforms are caller-owned synchronous pure callbacks, once per derived stat
after its resolver, including disabled stats. They are not captured in snapshots.
TypeScript cannot enforce purity or determinism of closed-over mutable state.
Disabled stats still produce resolved/uncapped diagnostics and return value zero.
Enabled precision uses exactly `Number(value.toFixed(decimalPlaces))` and
re-clamps. Legacy supplies precision four; Kernel has no global default precision.

No new finite-value rejection is introduced. NaN/Infinity transform outcomes,
native precision exceptions and thrown caller error objects preserve JavaScript
and Legacy semantics. Existing modifier validation/error behavior remains in
the unchanged resolver. Cooldown keeps its finite/range checks and exact
`Invalid resolved cooldown` error, with `baseMs * (1 - effectiveCdr)`.
