## Implementation and public impact

Two additive Kernel exports, `captureNumericalOffenseSnapshot` and
`captureCalculationSnapshot`, reuse the existing three snapshot/context
interfaces unchanged. Their closed schema accepts ordinary records, dense arrays
and the declared numerical/string/boolean fields. It rejects unknown fields,
accessors, callbacks, symbols, non-data containers and cycles. Descriptor checks
do not invoke ordinary getters. The active-path cycle check allows shared aliases.
No finite/range normalization is imposed: NaN, infinities, negative zero,
explicit undefined in optional fields, dynamic keys and field order survive.

Capture performs one native `structuredClone` of the complete validated graph,
then recursively freezes the detached graph. Shared references within that graph
remain shared. TypeScript readonly restricts typed writes at compile time;
detachment removes input aliases; runtime deep freeze prevents writes to the
captured records/arrays. The input is not frozen. Numerical capture conveys no
Root/Child trust or session authority and stores no RNG/callback state.

Internal `cloneSnapshotData` and `freezeSnapshotData` are not exported through
the Kernel barrel. Legacy `actorOffense` still clones the two modifier lists
separately, and `snapshotActorOffense` still clones the full Root envelope once
inside the existing catch boundary before freezing it. Closed numerical schema
validation is never applied to raw Legacy offense. `invalid_root_offense`
mapping, default mutable aliases and trusted Root S0 identity remain intact.

No accepted .3-.7 calculator, public contract, Root Offense, Skill Execution,
Skill Integration, Instance, Trigger or DoT production implementation changed.

framework is introduced. Numerical captures intentionally reject cycles, while
Legacy retains its historical native clone/freeze behavior.
