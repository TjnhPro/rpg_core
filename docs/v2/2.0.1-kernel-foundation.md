## Ownership and package surface

`src/kernel/index.ts` contains only `export {};`. It owns the boundary for future
calculation contracts, reusable numerical rules, internal numerical utilities and
explicitly state-transitional primitives. No calculation, contract or placeholder
API has been introduced, copied or moved. No speculative subdirectories exist.

Consumers can independently import the empty native ESM namespace:

```ts
import * as kernel from '@rpg/core/kernel';
```

The additive `./kernel` package export maps types to `dist/kernel/index.d.ts` and
ESM to `dist/kernel/index.js`. The ten old package entrypoints and their 243
public symbols remain Legacy. Root and existing domain barrels do not change;
Kernel is not re-exported from root. Package name, version 1.0.0, ESM format,
dependencies, lockfile, VERSION, export manifest and historical preservation
fingerprints are unchanged. Internal deep package imports stay blocked.

Legacy retains all current stat/modifier/damage/defense/resource calculations,
validation, Skill admission/execution, Root/Child trust, targeting, trigger queues,
delivery/Spatial, effect/DoT lifecycle, state writes and event order. Future approved
Extract & Delegate changes must move one canonical calculation and retain its old
facade, never introduce parallel calculators. New gameplay/skill systems can use
Kernel independently without adopting the Legacy Skill Engine.

## Dependency enforcement

Allowed direction is `Legacy / Gameplay → Kernel`; Kernel can depend only on
Kernel files. The eight Legacy domains Stats, Modifiers, Damage, Combat, Effects,
Skills, Mechanics and Spatial gain permission to import Kernel. Legacy Contracts
retains its existing allowance; no other Legacy edge is opened.

The existing [architecture checker](../../scripts/check-architecture.mjs) recognizes
Kernel using its single domain allowlist and shared AST dependency traversal. The
same check applies to every nested Kernel file, not just its barrel. It rejects
Kernel dependencies on any existing Legacy contract, domain, root barrel,
application module, npm package or Node built-in. Existing import/re-export,
type-only and inline-type syntax, import-type expressions, import-equals,
dynamic import and require all pass through the same gate. Internal Kernel barrels
cannot hide a forbidden edge because their source files are checked too.

Unknown domains, invalid relative targets, external/nonliteral dependencies,
duplicate canonical declarations, exact historical forwarders/module-map and runtime
cycle protections are retained. Kernel-internal runtime cycles are forbidden;
existing Legacy type-containing cycles remain reported, not reclassified as fixed.

## Positive and negative evidence

[Architecture tests](../../tests/tooling/architecture.test.ts) invoke the real checker
as a subprocess against isolated temporary source trees, using the checker's existing
optional-root argument. They never mutate production source or create fixture
files in production Kernel.

- Positive: empty Kernel, actual source tree/root barrel/27 historical forwarders,
  Kernel-only imports and re-exports, and each of the eight Legacy→Kernel edges.
- Negative: 22 dependency forms/domain combinations run at both Kernel `index.ts`
  and a deeply nested file. Each target-only fixture first passes, then the forbidden
  edge must fail with its exact source/target boundary diagnostic, not a missing file.
- Additional negative cases cover root→Legacy Contracts forwarding, external packages
  and built-ins, nonliteral loading, invalid targets and Kernel runtime cycles.
  Existing regression cases retain duplicate/shim and Legacy edge enforcement.

The installed consumer smoke retains every previous scenario. It additionally checks
both Kernel archive members, native ESM loading with zero namespace keys, strict
NodeNext type resolution without ambient Node types, no placeholder calculation
export, and blocked Kernel deep imports. Existing domain→root namespace identity,
all 27 historical namespace identities and deterministic gameplay assertions remain.

## Limitations and next milestone

This gate enforces supported source dependency syntax, not complete transitive
emitted-declaration semantic isolation or every possible JavaScript metaprogramming
pattern. Duplicate declaration fingerprints are not proof against independently
rewritten arithmetic; canonical ownership still requires review. Existing type-cycle
paths are Legacy constraints. Unknown downstream consumers and other environments
are not independently certified by local regression/installed-consumer evidence.

v2.0.2 owns Universal Calculation Contracts and independent Kernel declaration
fixtures under a separately approved plan. No generic stat registry, damage engine,
resource implementation, gameplay feature or optional package extraction is included
here. Stop after v2.0.1 verification for Developer review; no automatic merge,
release, publication, tag or next milestone.
