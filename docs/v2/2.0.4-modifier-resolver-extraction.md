numerical aggregation. `@rpg/core/kernel` adds exactly three runtime APIs:
`selectCanonicalModifiers`, `prepareNumericalModifiers`, `matchesAnyTag`; and
three contracts: `ModifierAdapter`, `ModifierSourceSelection`,
`PreparedModifierResult`. Inventory: 50 symbols (44 types, six runtime functions),
11 reachable declaration files. Its existing 44 symbols remain compatible.

`JSON.stringify` equivalence, live source activation sets, validation and
damage/tag vocabulary. `prepareModifierResolver` projects the same seven fields,
without a second numerical calculation. The v2.0.3 prepared resolver seam is
reused without editing Stats. Negative `damage_bonus` remains valid; nonempty
conditions remain rejected. No condition engine, Damage B0/B1, Skill Runtime or
resource calculation was changed.

Source filtering completes before enabled/dedup checks. Identical duplicates
retain the last original object. Preparation fixes target groups, not their
mutable contribution objects/arrays. Operation and value reads retain the three
separate filter/reduce passes and floating-point order. Present groups retain
their array alias across resolves; missing groups get fresh arrays. Original
exceptions propagate without wrapping. Event context lookup remains inside each
required-tag branch; type/scope/event mismatches short-circuit before later reads.
Target fallback is still evaluated at its historical point, even for attacker-only
matching. Reason precedence is unchanged.

The compatibility review emits the accepted HEAD's declarations in memory and
