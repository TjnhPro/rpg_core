## Cause and correction

The initial v2.0.3 adapter eagerly copied scalar bounds and materialized every
attribute/derived numerical rule before callbacks ran. Legacy before extraction
observed standalone scalar rules after callbacks, and selected character rules
one at a time. Stable-input parity did not cover these mutable configuration cases.

Only `src/stats/stat-calculation.ts` production code changes. The standalone scalar
wrapper supplies getters for min/max/enabled, so the canonical Kernel scalar reads
the original rule after resolver and transform, including re-clamp. Optional max
maps to Infinity; precision remains the supplied argument.

Character rule records expose per-key numerical accessors. A future rule is
selected on its turn, allowing earlier callbacks to change or replace it. That
selection captures scalar bounds/enabled before the current stat's callbacks,
as the pre-extraction character adapter did. Bases and flat extras also use
per-key accessors, so earlier callbacks can update inputs of later stats.
Baselines remain caller-owned inputs. No completed attribute/stat is recalculated.

This distinction preserves both late reads and already-captured values; it does
not make all fields live after callbacks. Kernel's existing loops, scaling,
transform, clamp, precision and diagnostics are untouched. Public Kernel types,
signatures, all implementation files, contracts, Modifier Resolver and resource
calculation are unchanged. There is no new cache, engine, registry or contract.

Legacy compatibility does not require callers to make existing callbacks pure.
Universal Kernel callers continue to own stable numerical inputs when they need
determinism. No Legacy/Game configuration type is imported into Kernel.

## Exact mutation oracle and regression evidence

`scripts/capture-stat-mutation-golden.mjs` reads Stats source from exact original
revision `a05439ec504b759df48d3345eea199fecf08083f`, transpiles it in memory, then
captures outputs using unchanged Legacy contract/modifier modules. This is a
manual capture tool, never used by production or runtime parity tests. Capture
asserts the reviewed HEAD and unchanged contract/modifier sources. Source SHA-256
and revision are recorded in `tests/fixtures/stat-mutation-golden.json`.

Existing 38 golden scenarios and their JSON are untouched. The new fixture has
38 additional scenarios: 13 scalar and 25 character cases. Tests compare complete
nested outputs, diagnostic contributions, resolver/transform call traces and
counts, error names/messages and original callback-error identity. NaN, Infinity
and signed zero use the existing lossless encoder. Additional direct assertions
check original resolver result, contribution array/object and thrown error
references during mutation. No runtime test computes expectations with the old
calculator or uses approximate equality as its oracle.

Cases include resolver/transform changes to scalar min/max/enabled, disabled and
NaN/Infinity transforms, precision re-clamp, callback throws, future attribute
bounds/rule replacement/base changes, attribute-to-derived changes, derived rule
replacement/fallback/scaling/default/bounds, later base/extras/baselines,
elemental policy/dodge override and transform changes to a later stat.
Negative controls mutate current attribute/stat inputs after their capture,
including elemental enablement and dodge configuration, and retain the original
current result. Stable-input controls remain covered.

Running the same new observer against Stats from the reviewed `d57feee` revision
detects **23 failing scenarios / 38** against the original oracle. With this patch,
all 38 pass. Independent Text RPG, Võ Lâm and ARPG Kernel fixtures still pass.
